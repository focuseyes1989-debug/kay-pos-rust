# KAY POS 0.2.1

- F4 now opens Checkout on the Sales page, including when product search is focused. Empty carts, open dialogs and the sidebar block the shortcut.
- The sale-saved dialog now uses Close as its primary action; Print Receipt is secondary.
- Theme and appearance colors are now local to each Windows user on each client PC. Existing database appearance is imported once; subsequent changes on other PCs do not replace local preferences.
- The login screen centers the version, update buttons and update status.
- Settings > App Updates uses a styled primary Check for Updates button.
- Desktop assets are self-contained in the Rust source project.

## Updating

For clients on 0.2.0: finish work, sign out, choose Check for Updates on the login screen, then Download & Install and Restart KAY POS. Pilot on one client first.

Older clients without an updater need one manual installation. Keep existing database connection settings. No database migration is required.

Upgrade every client to get local appearance behavior. Each upgraded client initially imports the server's current appearance; choose its preferred theme afterward. Preferences are stored in `%LOCALAPPDATA%/KAY POS Rust/appearance.json` and survive application updates.

The ZIP contains only pos_desktop.exe and carries the existing trusted update signature. No source code, database credentials, shop data or private signing keys are included. Windows x64 and WebView2 Runtime are required.
